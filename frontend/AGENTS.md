# 正式游戏前端的设计约束

本项目使用正式 `/play` 页面验收；不要另做预览页代替真实界面。

## 视觉修改的对照依据

- 用户指定的构图原图：`../docs/design-reference/20261030-story-stage-target.png`。
- 本轮局部对照、素材与检查记录：`../docs/前端折页与通用立绘验收-20261030.md`。
- 之后如用户提供新的目标图，以最新明确指示为准并更新对照记录。

修改主界面后，要实际打开正式页面，逐项看：正文与立绘的交界、蓝色折影的前后层次、人物前方的纸页斜切、输入区下方的回折边、文字可读性、控件是否被装饰挡住。需要对照原尺寸时用 1672 × 941；同时看正常桌面和窄屏，并恢复临时视口设置。保存真实截图，不能仅凭构建成功声称达到视觉效果。

左侧导航形状是用户反复确认过的内容。仅修改立绘或装饰时，不要擅自改变输入区尺寸或导航形状。2026-10-30 用户再次明确指出“边角和输入框都有问题”，已按预设图把输入区调整为横向薄带、输入框与按钮平行斜切、纸角贴近按钮；以对照文档中的最新实测为准，不要恢复此前 40px 高、短输入区加大三角的错误组合。之后的控件改动仍需依据用户的新指示。

## 立绘的呈现

- 优先使用已有具体立绘；没有精确命中时，按兼容题材、性别、儿童边界和最多公开特征选择近似图。
- 没有兼容图时使用通用匿名留影；不得因为关键词零重叠、性别未知、儿童或题材暂缺就把整块人物舞台留空。
- 保留原图失败 → 通用素材 → 内置离线图形的加载保护。切换人物不能反复重试坏图或闪成空白。
- 限知展示不能从角色名字、隐藏档案或私人心理推断真实身份。通用留影是艺术示意，不回写故事事实、物品和行为；独行画面不能新增虚构 NPC。
- 通用素材和原立绘都可多人共用。不要在每次生成新角色时追加付费生图调用。
- 新增正式素材要存入 `public/art/`，提供标签并同步图鉴；不要让正式页面依赖工作区外的临时生成路径。

纯前端修改使用相关离线回归与生产构建，并实看受影响界面；不要为了美术验收提交新的付费故事行动。故事逻辑和后端在本次纯视觉任务范围之外。
