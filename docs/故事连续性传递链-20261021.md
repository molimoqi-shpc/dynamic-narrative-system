# 故事连续性传递链（2026-10-21）

本轮处理的是前段实际结果能否进入下一段，而非增加场景资格、关键词或逐动作判定。全部正文仍由主API创作，角色API只提供自己的意愿。

## 修复

1. **累计摘要归档缺少旧摘要。** 主创原本会收到`storyMemory`，但定稿归档输入只包含当前世界、角色索引和面板等资料，却要求归档生成下一份累计摘要。现在归档同时获得此前累计摘要、玩家已获知的重要原始事实及紧接本段的已发布正文。它在旧摘要上更新结果，保留仍相关的早期因果、已完成问题、重要归宿和未了关系，不将已解决事件重新悬置。原始候选表和未执行计划仍不作为已发生事实传入。
2. **长上下文末尾缺少整体承接。** 主创写作上下文提供累计摘要和最近实际结尾；后续分层改造中，末尾改为精简引用指引，原文仍完整保留在同一请求内，避免读完大量角色表后仅承接最后一句。要求证据足够时兑现答案、后果和阶段收束；普通调查授权涵盖顺势问询和查看，不能永久仅增加一个同样不知情的人。
3. **新人物缺少玩家身份标识。** 既有人物和候选新人物统一绑定本人/玩家身份与本次玩家方向，避免把玩家第一人称变成NPC自身持物或行动。
4. **同一回合内部接续与重做混淆。** 角色请求现在明确本轮已有多少段落被实际提交，仍只给予本人亲历和当前处境；不会将其他人的正文或私有事件广播给该角色。原方向是持续方向，已亲历完成的部分不再作为新目标重演。

没有新建任务清单、地点许可、时间限制或剧情结果判断。新增上下文直接使用已有保存资料，不增加模型调用次数；归档请求携带相关旧资料，会略增加该次输入量。

## 程序回归

125项相关测试通过：SceneStoryIT 63、SceneStoryServiceTest 15、StoryAuthorContextTest 9、StoryArchiveIT 7、StoryArchiveServiceTest 2、DeepSeekEmptyResponseTest 5、LLMBillingObserverTest 7、LLMRequestPolicyTest 8、StorySceneOutcomesTest 9。最终主创上下文、归档和场景保存20项另行复跑通过，不重复计数。另有1次显式开启的真实归档探针，默认不运行收费测试。

新增测试覆盖累计摘要进入主创最后一条消息、归档输入保留累计摘要和原始事实、优先承接本轮最后已发布段落、候选表不污染历史、新人物身份和接续阶段不泄露其他人的经历，以及累计摘要跨六轮仍保留早期已解决事实。六轮测试使用模拟模型响应，作用是验证数据传递，不能冒称真实故事游玩。既有归档失败恢复、落库回滚和新人物接入回归一并通过。

真实模型接续实测及费用另见聊天工作目录`outputs/故事连续性优化与实测-20261021.md`与`outputs/连续游玩实录-20261021.md`；不能仅依据程序测试保证任意长篇永远无错。

## 实测后追加修复

主API归档现在先从完整定稿正文整理endingCast人物最终场景及依据，再按终点保存sceneOutcomes，避免将途中地点或旧出发点当终点。不在程序里按地点关键词推断剧情。角色回复的非空格式错误由操作层保留原文，避免provider直接丢弃并自动重抽；恢复复用成功人物。主创末尾同时明确整段以玩家所求事情为单位，普通抵达与问路不等于完成调查，篇幅建议不应截断结果。

真实模型最终分支共5轮，含此前开头1轮和本轮新增4轮。额外对原先归档错误的同篇定稿做1次只读真实归档复测，正确分组院中访客及离场者，不写回游戏。完整实录和费用在前述报告；末轮仍有船已在场却说等船回来的时间线矛盾，完整调查尚未收束，完整故事验收未通过。主创新增成稿前自行通读时序与当前事实的要求，最后这项提示调整只做程序回归，未追加收费复测。不以接口COMPLETED冒称全部故事已经完结。

## 主创输入分层与收束约定改造

2026-10-21后续按用户指定完成1—3项：StoryAuthorInput只整理主创请求副本，归档及NPC本人资料保留完整。最新意愿去重为同请求引用，已归档旧心理转为世界书按需查询，尚未归档者分层保留；玩家与NPC记录使用明确顺序元数据。正文创作使用独立提示，最后以精简事实来源、人物表引用和episodeFocus组织自然行动及阶段后果，不加剧情判定或额外模型调用。124项程序回归与打包通过；一份旧真实上下文离线回放的资料字符量减少17.5%，详细心理表保持一致。新增收费调用0，十几轮真实故事实测留待用户后续安排。完整说明见当前聊天outputs/主创上下文分层与阶段收束-20261021.md。
