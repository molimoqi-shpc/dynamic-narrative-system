# 角色档案与世界书（2026-10-19）

全部最终故事、对白和行动结果由主 API 创作。角色 API 只产生本人心理、意愿及参与方向；这些内容不会直接作为玩家正文发布。

## 档案分层

重要角色使用 `CORE` 档案，普通龙套使用 `EXTRA` 简版。角色 API 根据已有经历、持续目标和实际剧情关系选择，不以名字、职业或六维数值机械判定。重要角色暂时沉默、离开、与主角不熟，不构成降级理由。服务器承接已有重要人物档案，防止原有细节丢失。普通龙套在后续真实形成持续剧情或重要关系时可以升级。

玩家使用 `PLAYER` 档案：保存真实身份、身体、物品、经历及玩家输入的大致方向，不替玩家生成未表达的心理、爱慕、承诺或立场。

每份档案分开保存以下内容：

| 区域 | 来源与用途 |
| --- | --- |
| identity | 已确立的自我资料、六维、目标，由服务器提供 |
| currentState | 当前身体、物品、物品位置、已登记情绪及工作，由服务器提供 |
| personallyKnown | 实际见闻、认识的人、最后观察、本人收到的刺激，不是全知广播 |
| pastInformation | 保留的亲历与既有背景，不由当前心理模板重写 |
| psychology | 角色 API 对事实的主观理解、情绪、人设及未发生意愿 |
| intentions | 本次完整事情的想法、目标、行动方向、交流态度和底线 |

事实与心理不一致时，以真实记录为准。资料不足使用未知、null 或空数组；模板列出童年、羞耻、依恋等可能维度，不表示必须替人物编出这些经历。

## CORE：12 个分区、113 个直属细项

完整字段定义集中在 `backend/src/main/java/com/bs/narrative/service/CharacterTemplateSchema.java`。113 项统计不另计条件分支内部的 if/then，也不包含服务器绑定的身份、身体、物品、过去记录等事实字段。

| 分区 | 内容 |
| --- | --- |
| selfConcept 自我认知 | 自我形象、认同的责任、自尊依托、期望形象、内在矛盾、身份疑问 |
| personality 性格 | 稳定特点、长处、缺点、日常性情、习惯、放松表现、压力反应、不同处境的矛盾面、改变条件 |
| values 价值观 | 核心价值、优先次序、道德底线、忠诚、禁忌、骄傲、羞耻、权力观、信任观、价值冲突 |
| emotionalState 即时情绪 | 主次情绪、强度、起因、外在表现、私下感受、未满足需求、担忧、期待、触发点、调节方式、较上次的变化 |
| cognition 判断与限知 | 注意力、对新经历的解释、确认事实、听说、猜测、未知、偏见、判断把握、可能误解 |
| motivations 动机 | 长期、近期、眼前目标，优先级、个人利害、可接受与不可接受代价、确有依据的隐秘目的、紧迫性、成功标准 |
| relationships 逐人关系 | 每个实际认识者的 id、已知身份、交往依据、公私态度、信任、戒心、已形成情感、债务承诺、期待、合作范围、矛盾、披露范围、最新变化、改变条件 |
| memoryInterpretation 过去理解 | 重要亲历、累计过往、近期亲历、未解线索、已履行与未履行承诺、后悔、教训、新事实对旧事的重新理解 |
| expression 表达 | 语体称呼、节奏、措辞习惯、非语言习惯、主动谈的话、被问才说的内容、保留信息、拒绝方式、争执方式、关怀方式、确有依据的欺瞒意图 |
| cooperationAndConflict 合作冲突 | 愿参与的完整事情、主动方向、不容商量与可商量事项、对实际结盟/敌对/亲近关系的态度、风险承受范围、改变立场条件 |
| actionPlan 行动方向 | 完整事件方向、原因、普通事务自然接续、条件分支、遇阻替代方向、停止条件、真正需要玩家决定的事项、未发生标记 |
| continuity 连续性 | 保留的人设锚点、相比上次变化、变化原因、未解矛盾、需要查阅的旧事 |

这些栏目帮助主 API 统一塑造人物，不把人物变成逐秒执行清单。普通询问、关怀、调查、赶路可以自然连续完成；结盟、敌对、表白、重大承诺与风险等才停在玩家表态前。

## EXTRA：只填 6 项

`roleInScene`（现场身份职责）、`immediateConcern`（眼前关切）、`attitude`（简单态度）、`willingHelp`（愿意做或回答什么）、`knowledgeLimits`（实际知道的范围）、`boundaries`（明显不愿做的事）。

龙套不填重要人物整套性格、童年、创伤、隐秘动机、逐人关系等心理细节。其真实身体、物品、身份与已发生历史仍照常保存，不会因为是龙套而丢失世界事实。

## 续接、存储与用量

- 角色 API 读取本人 `previousPsychology` 和 `previousPortrayal`，承接稳定人设与累计过往，结合新经历更新即时状态。旧版八字段模板兼容读取。
- 返回协议使用一个根对象，五项意愿与分级位于根层，详细分区放在 `characterTemplate` 内。模型把分区展平或漏写根层意愿、但已经写出明确眼前目标时，可从相应字段无歧义读取；不根据性格猜一个目标。恢复先重读同帧已保存的回答，避免格式修复后重复调用角色。
- 详细档案归档为世界书 `CHARACTER_DOSSIER`；全部保留的个人历史导入 `CHARACTER_HISTORY`，以来源引用去重。它们均为私有资料，所属角色与实际接收者隔离。
- 主 API 收到 `characterDossiers` 与 `worldBookIndex`，可以通过 `worldBookRequests` 按人物分页查阅更早历史，结果放入 `worldBookResults`。查询不推动故事时间，也不重新抽取角色意愿。
- 主 API 每次收到的心理模板只有一份；角色上下文、意愿字段不重复塞入相同模板。旧心理完整存世界书，近期过程不反复携带每一轮的完整模板，避免长局输入不断膨胀。
- 详细角色请求输出上限为 10000 token，属于上限而非每次必须使用的额度；普通龙套仍只生成简版。角色生成与主 API 创作分别计算时间预算，避免角色模板较长时挤掉正文生成时间。
- 整章按短事务保存；模型调用在事务外。档案、历史与其他世界状态一起进入原有检查点，随正常回溯恢复。
- 世界书正文列扩大为 MEDIUMTEXT，避免长档案超出旧 TEXT 容量；不执行初始化 SQL，不清空已有存档。

模板提示与程序测试不能保证模型永远不偏离人设；实际剧情还需要用全文和真实状态对照验收。

2026-10-20 补充：重要人物本段只更新部分心理分栏、或短答没有重复整份模板时，按字段承接此前本人记录，不清空未更新的价值观、关系与过往理解；嵌套分栏也保留未改的小节。本次明确给出的内容覆盖旧主观记录，数组按本次完整值替换，玩家心理仍不由程序或模型补定。沿用旧记录不表示本段重新确认，身体、物品和真实亲历始终单独保存。


## 2026-10-19：主 API 的最终亲历回写

角色 API 的意愿不直接执行。主 API 汇总各人的模板、玩家方向、前文与世界书，统一创作结果；同行者是否抵达、途中意外与具体后果也由主 API 决定。每段可只有完整正文，不需要逐句动作事件。

主 API 返回每名参与角色的 `roleExperiences`：`experience` 是本人实际亲历与所闻，`situation` 是累计重要处境、关系、承诺与线索。分别保存为本人的私有经历与 `story:situation`，下一轮传入本人档案的 `currentState.storySituation`。玩家正文单独保存为玩家经历，不把整段故事广播成所有 NPC 都知道的记忆。它们与重要状态一起回溯。

角色意愿新增可选 `itemIntentions`，仅填写本段有关的物品、交接方向、对象和条件，不填写每件物品的微小位置。程序不会根据意愿自动交接，也不会根据愿意同行自动移动角色。旧姿势、细动作和未完成计时工作不成为新段落必须逐项完成的清单。新主流程详见[故事优先运行链路](故事优先运行链路.md)。
