# 小说长轮实测与修复（2026-10-21）

玩家意愿是本轮叙事焦点，主 API 根据实际前文、人物意愿与局势创作能否实现。可以合理推进时推进，也可以拒绝、失败或只完成一部分；不为迎合玩家改写人设，不为制造曲折强加阻碍。角色 API 只提供本人档案和意愿，全部正文仍由主 API 创作。

## 本轮实现

- 正常定稿前创作用独立 `STORY_AUTHOR` 请求策略，最大输出 12288 token。真实网关在思考模式和后来的非思考请求中都出现过空白内容；最终仍使用非思考 JSON 模式，不能宣称网关空白故障已根除。
- 玩家原方向、已经提交的段落数和结果决定权放在每次请求末尾。普通票价、打包、住宿不自动成为重大承诺；主创需围绕实际事件组织结果，不能保证玩家成功。
- 主创可返回 `authorPlan`，跨补人物、换场和恢复保存在 `episodePlan`，标记 `UNCOMMITTED_AUTHOR_PLAN`。这是主创自己的可变写作备忘，不是历史事实，不发送给角色或玩家，也不由程序执行其中设想。
- 开篇已发布原文离开最近四轮窗口后，另以 `openingPublishedChapter` 保留实际起因；归档也能读取。初始角色设定和累计摘要不能把早期已经发生的行为变回未发生。其余更早细节仍可按角色世界书索引查阅，不等于所有历史都已常驻上下文。
- 末尾阅读提示保留每人的真实编号、姓名及原始身份来源，帮助主创区分各人的身世与亲缘；不从关键词猜亲属关系，不通过程序重写对白。
- 已付费的主创空白或坏 JSON 原文先保存，暂停同一操作，成功角色意愿复用。恢复时不把空白故障对象作为助手示例再次喂给模型。
- 归档准确且唯一的人名可以对应本存档已知编号，不猜别名或同名者。若正文涉及真正漏建档的新人物，归档不能自行编身份：保留原回复与已发布正文，只将当前未发布候选交回主创补资料、取得本人意愿后定稿。这是“归档仅重试归档”原则的明确例外，不能改写已发布历史。
- 新物品自编的临时编号会绑定到服务器创建的编号，并同步同次人物面板资料的结构化引用；已有物品可按准确且唯一的名称对应原实例，不因占位编号再生成一件。新取得仍需要实际名称、持有人与正文归档的取得来历，不修改正文来配合存档。
