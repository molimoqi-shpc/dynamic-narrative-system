# 连续游玩稳定性补修

本轮从 2026-10-30 夜间持续至 2026-10-31，目标是加固正常连续游玩的主流程。日志沿用开始时的 `20261030` 前缀。

## 主要改善：提交冲突后恢复到可继续游玩的状态

原先服务器已推进进度、改变分支，或已接受另一标签页的行动时，新的提交会返回 `200009`。页面仅清除本地待处理标记并显示错误，正文、场景与提交版本仍旧；再次提交可能继续失败，也不能直接接管服务器已在生成的内容。

修改前评估：

- 收益是解除连续行动中的过期状态，恢复到服务器保存的进展，并找回服务器已有的待完成操作。
- 额外开销仅发生在已确认的提交冲突后，使用现有的免费场景和章节同步流程；普通成功提交不增加步骤。
- 保留玩家输入，让玩家阅读最新进展后决定下一步。没有自动重发行动、自动追加模型额度或改写已有章节。
- 同步暂时失败时使用既有的重读入口，避免在未知进展上不断提交新行动。
- 复用已有的一致性读取和操作轮询，不另建故事、地点或时间判定机制。

实际修改位于 `frontend/src/views/PlayView.vue` 的 `submitOperation` 异常分支。新测试先在旧实现上复现了三种失败，见 `../.runtime/stability-20261030-action-conflict-before.log`；修复后验证：

1. 提交冲突后同时恢复最新场景和章节，原输入保留；玩家下一次主动提交使用新版本并完成下一轮。
2. 冲突后的读取失败仍可重试，同步恢复后可继续行动，不重复提交原请求。
3. 服务器已有生成任务时接管原操作标识，免费轮询到完成；玩家准备的下一步输入保留。

## 已完成的两处相关防护

- `CharacterCreationView.vue`：开局初始化重试返回后，继续生成世界前确认仍属于本次初始化的存档。修复的是旧重试流程可能对新选存档发起世界生成的问题；自己的正常重试仍可继续。接口和世界生成规则不变。
- `PlayView.vue`：取消并修改输入时，异步取消完成后的文字恢复也遵守原账号、存档、分支和页面归属，避免把旧行动填回新的进展。

这两处修改前的三个失败案例记录于 `../.runtime/stability-20261030-races-before.log`。修改仅影响过期流程的后续处理，不更改正常开局、正常取消编辑的行为。
