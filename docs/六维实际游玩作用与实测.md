## 实测发现与修复

1. 初始低组12对42，被主创写成NPC滑倒、玩家获胜，完全没有请求CONTEST；高组也没有登记数值后果。原始错误故事和费用保留，这两轮不算通过。
2. 角色API现可用contest明确本次实际交手意愿。服务器在主创首次写正文前提供条件性结算参考，不执行角色意愿，不自动扣血；正文确实交手才提交CONTEST。普通交谈不触发。
3. 后续复测中，主创漏填CONTEST执行者导致错误归到玩家。现在只依据本次唯一结算指纹补齐遗漏编号，保留明确填写的编号，不解析正文或猜胜者，不为补编号付费重写。
4. 结算参考补充带双方编号的生命前后值及明确后果，要求正文、亲历与生命一致，避免正文说双方无伤而存档扣血。再次复测中，低组胜负和受伤正文已符合公式，但主创仍漏填CONTEST，实际生命没变，该轮也不算通过。现在主创只需在contestResolutions标明本场是否实际发生，服务器按对应指纹保存同一个公式结果；未发生时不扣血。它不按正文关键词或角色意愿猜测是否打起来。
5. 一次角色模型服务失败和一次保存失败都没有发布正文或改变生命。原操作通过正常取消接口取消，未删除失败记录或手改存档；修后以新操作完成对照。
6. 先前新角色仅有中性占位数值，下一轮却可能被当作真实能力。现在以明确标记保留未知，角色、主创与当前交手入口一致承认尚未确立能力，不以15点占位裁定强弱。
7. 公式面板移除“归为0即死亡”“高属性可以查看秘密”和将旧演示干预规则当作当前玩法的过时说明。
