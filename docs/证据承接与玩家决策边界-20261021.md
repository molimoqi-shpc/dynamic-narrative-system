# 证据承接、玩家边界和事件收束（2026-10-21）

## 本轮修改

1. **重要剧情保留最初出处。** 剧情与伏笔 JSON 增加 `originalSource`，后续进展只更新当前 `source`。旧条目可从世界书最早快照恢复原出处。模型不能用后续归档覆盖这份源记录；不增加数据库表。
2. **主创实际带回较早原文。** 已发表章节保留 `logId`。准备创作上下文时，按重要剧情最初出处取回不在最近四章及开篇中的原章节，至多三份、总计六千字符；同章节不重复发送。过长原文不截断冒充完整证据，保留按需查档入口。原文也进入定稿归档上下文，角色 API 不接收这份全局资料。
3. **末尾写作焦点提供证据阅读顺序。** `StoryEvidenceContext` 按实际字段提供原问题、原始铺垫、已回收结果与原文路径。主创在既有 `authorPlan.establishedCauses` 中区分材料实际说明的内容与尚不能证明的部分；人物说法和本段新发现不能变成玩家此前早已核实的证据。程序不理解或裁决剧情文本。
4. **明确人类玩家控制的姓名与编号。** 原本详细附加表已有 `isPlayer`；本次在最后写作焦点增加 `playerControl`，在人物阅读索引区分 `HUMAN_PLAYER` 与 `CHARACTER_INTENTIONS`。主角未决定的信任、承诺和担保不能按 NPC 自主反应处理，也不替玩家选择暂缓、初步相信或离场回避。
5. **同一场景自然写完。** 普通问答、展示材料、解释条件及自行补注，由已有角色意愿支持时在同次正文自然完成。主创只在实际新变故导致所需意愿不足时考虑 `CONTINUE`；真实新重大提议及后果讲明后，以 `DECISION` 等待玩家。这里只调整主创职责和上下文，不增加程序剧情判断、关键词过滤或停点重写。
6. **界面显示具体后果。** 主创生成的 `decision.stakes` 随 `storyStop` 保存进章节快照，`StoryDecisionNote` 在问题下显示其责任、代价或风险。普通进展不显示旧选择后果，主创私有构思不会进入界面。
