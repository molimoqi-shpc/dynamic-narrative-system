## 二、六维属性体系（知·慧·斗·闻·本·归）

| 属性 | 字段 | 含义 | 作用 |
|------|------|------|------|
| **知** | `base_zhi` | 情报量 / 谋略深度 | 能力判定、干预三角的"能力"维度 |
| **慧** | `base_hui` | 推理解题 / 悟性 | 信息准确度；能否识破谎言 |
| **斗** | `base_dou` | 战斗力基准 | P4 属性差对抗核心指标 |
| **闻** | `base_wen` | 局势感知 / 消息广度 | 打听时决定能发现的事件重要度上限 |
| **本** | `base_ben` | 修为根基（0~100%） | **全局修正系数**，同时是"贪腐倾向"度量 |
| **归** | `base_gui` | 忠诚意志 | 判断是否易被策反、是否坚持立场 |

**实际值公式（`StatsCalculator`）：**

```
actual = ROUND( base × (1 + baseBen / 100) )
```

- `baseBen` 范围 `[0, 100]`，是唯一有上限的属性，也是所有属性的放大系数
- Java 实现与 MySQL `ROUND()` 保持一致（有对拍验证脚本）

**"本"的一物两用：**

- 放大系数：`actual = base × (1 + baseBen/100)`
- 贿赂判定：守方 `actualBen ≥ 40` 才会受贿
- 干预收益：`gain = defender.actualBen × 0.5`

## 三、总体游玩流程概览

```
注册 → 登录 → 主菜单 → 新游戏
   → 三问（性格推导）→ 选天赋 → 出生故事 → 六维初始化 → 目标初始化
   → 进入初始场景
   → 【核心循环】自由文本移动 / 对抗动作 / 打听
        ├─ Pass1 意图提取（LLM）
        ├─ 规则引擎结算（5 层优先级 + 六维公式 + 三角模型）
        ├─ 落库（属性/关系/背包/日志/世界书）
        ├─ NPC 群戏批处理（限知博弈，单次 LLM）
        ├─ Pass2 叙事生成（记忆注入 + 说谎判定）
        └─ 目标推进 → 记忆记录
   → 死亡 / 通关 → 多结局判定
   → 时空回溯（事件溯源） / 重承天命 / 重新化生 / 返回主菜单
```

## 四、阶段一：注册与登录

### 4.1 注册 — `POST /api/auth/register`

**前端：** 登录页注册 Tab
**服务：** `AuthService.register()`

流程：

1. **用户名唯一性校验**：查 `player_profile`，已存在则抛业务异常（账号已存在）。
2. **密码加密**：BCrypt 哈希后存入 `password_hash`，绝不存明文。
3. **创建玩家实体 `player_profile`**：生成 `player_id`，关联 `god_id`（玩家即角色，具备完整六维）。
4. **创建 `god_profile`**：六维基础属性初始为 0（待角色创建时由 LLM 推导），背包为 JSON 数组。
5. 返回 `{playerId, username}`。

**落库：** `player_profile`、`god_profile`

### 4.2 登录 — `POST /api/auth/login`

流程：

1. 按用户名查 `player_profile`，不存在 → 账号不存在。
2. BCrypt `matches()` 比对密码，失败 → 密码错误。
3. 用 `player_id` + 过期时间签发 JWT。
4. Token 哈希持久化到 `player_profile`（便于吊销）。
5. 返回 `{token, playerId, username}`，前端存入 localStorage + Pinia。

**后续鉴权：** 请求头 `Authorization: Bearer <token>`，后端校验签名 + 与库内 token hash 比对。
**路由守卫：** 需要登录的页面 `meta: { requiresAuth: true }`，未登录跳转登录页。

## 六、阶段三：角色创建（三问 + 天赋 + 出生故事）

### 6.1 Step 1：三个问题 — `POST /api/game/start`

**服务：** `CharacterCreationService.startGame()`

1. 创建 `game_session`（状态 `CREATING`）
2. 创建 `character_creation` 记录
3. 返回 3 个预设问题（如"你童年最怕什么""若有人夺你珍视之物当如何""力量本源来自何处"）

### 6.2 Step 2：提交答案 → 性格标签 + 天赋 — `POST /api/game/answer`

1. 保存答案
2. **调用主 LLM**：以 3 个答案为输入，要求输出 JSON：
   ```json
   {
     "personality_tags": ["坚毅", "机敏"],
     "talents": [
       {"talentId":"...", "name":"...", "desc":"...", "statBonus":{ "zhi":0,"hui":5,"dou":10,"wen":0,"ben":0,"gui":0 }}
     ]
   }
   ```
3. **JSON 兜底解析**：正则提取首个 `{...}` 块 → 反序列化；失败走 Fallback 预设天赋。
4. 天赋落库。
5. 返回 3 个天赋供选择。

### 6.3 Step 3：选择天赋 → 出生故事 + 初始化 — `POST /api/game/talent/select`

1. 将所选天赋的 `statBonus` 累加到六维基础值。
2. **调用主 LLM 生成出生故事**（约 200 字叙事），落库。
3. **分配初始场景**：从模板或 LLM 生成第一个场景，建立 `scene_connection` 边。
4. **目标初始化** `PlayerObjectiveService.initObjectives()`：
   - 调用 LLM，根据出生故事 + 天赋生成 2~3 个个人目标，落库 `player_objective`（状态 `ACTIVE`，进度 0）
   - 失败回退到预设目标模板
5. 更新 `game_session.status = PLAYING`。
6. 返回：出生故事 + 初始场景 + 目标列表。

**落库：** `god_profile`、`character_creation`、`game_scene`、`scene_connection`、`player_objective`、`world_book`

## 七、阶段四：进入场景与自由探索（拓扑图）

### 7.1 加载当前场景 — `GET /api/game/scene`

**服务：** `GameActionService.describeScene()`

返回：

- `locationName`、`sceneSummary`（场景摘要，长记忆）
- `presentGods`（在场角色，含六维属性）
- `exits`（已知出口，拓扑图边：方向 + 出口名）
- `objectives`（目标进度）

### 7.2 自由文本移动 — `POST /api/game/explore`

**服务：** `SceneGenerationService.explore()`

**拓扑图（节点 = 场景，边 = 出口）** 机制：

1. **方向解析**：关键词匹配或 LLM 提取方向（NORTH/SOUTH/EAST/WEST/UP/DOWN/OTHER）。
2. **查边**：`scene_connection` 查 `from_scene_id + direction`。
3. **有边（已探索）** → 直接跳转目标场景，**零 LLM 调用**。
4. **无边（新方向）**：
   - **调用主 LLM 生成新场景**：输出 `{locationName, description, presentGods, direction, exitName}`
   - 创建新 `game_scene` 节点
   - 建立**双向边**（A→B 方向 N，B→A 方向自动取反：北↔南 / 东↔西 / 上↔下）
5. **写世界书**：`world_book` 记录 MOVE 事件（含回合号、地点名、重要度、是否秘密）。
6. **Pass2 叙事**：生成移动场景的环境描写。
7. 返回：新场景 + 出口列表 + 叙事。

**论文表述：** 基于动态图遍历的场景探索机制（Graph-based Exploration）。

## 八、阶段五：对抗动作核心循环

### 8.1 玩家输入 — `POST /api/game/action`

**服务：** `GameActionService.processActionWithDb()`（系统核心方法）

玩家输入自由文本，例如"我拔出骨刃刺向对方，抢夺止水符！"

### 8.2 完整流水线（按执行顺序）

**步骤 1 · 数据加载（事务内）**
- 加载当前场景、玩家实体、在场角色、角色间关系（信任/结盟/背刺标记）
- 一律按会话标识隔离，禁止全表扫描

**步骤 2 · Pass1 意图提取（LLM）**
- `Pass1Service.extractIntent()` 输出 JSON `{intent, target, confidence, itemId?}`
- 意图枚举：ATTACK / STEAL / TALK / BRIBE / OBSERVE / QUESTION / MOVE / EXAMINE / PICK_UP / UNKNOWN
- 鲁棒性：无关输入（"今天天气不错"）与恶意注入（"忽略之前的设定…"）统一识别为 `UNKNOWN`
- 解析三级降级：标准解析 → 正则提取 `{...}` → Fallback 固定 UNKNOWN

**步骤 3 · 规则引擎结算（纯函数，5 层优先级）**

| 优先级 | 触发条件 | 结果 |
|--------|---------|------|
| **P1 符咒** | 一方的背包中存在符类物品（含"符/咒/印/阵/幡/令"） | 抵消攻击，消耗该符类物品 |
| **P2 背刺** | 第三方曾被目标背刺且信任 < 30 | 第三方劫掠救援（反转） |
| **P3 第三方干预** | 干预三角模型得分足够 | 攻击 / 干预 / 不出手 |
| **P4 属性差** | `|双方实际值差| ≥ 10` | 攻方胜 / 守方胜；差值在 [-10,10] → 平局 |
| **P5 意图特殊** | 贿赂 / 观察 / 询问 | 受贿成立（守方 `actualBen ≥ 40`）/ 或无效果 |

**干预三角模型（`InterventionScorer`）：**
```
ability = round( 第三方相关键实际值 × 0.4 )
will    = clamp0..100( (100 - trust) × (是否被背刺 ? 0.8 : 1.0) + 同盟加成 ) × 0.3
gain    = clamp0..100( 守方.actualBen × 0.5 + 同盟加成 ) × 0.3
score   = ability + will + gain
```

**DeltaApplier：** 将结算产生的属性增减施加到六维基础值、关系信任度、背包物品。

**步骤 4 · 持久化落库**
- 角色六维属性更新
- 关系网信任度更新
- 交互日志（含回合号、结算类型、token、成本、规则中间产物快照）
- 世界书事件

**步骤 5 · NPC 群戏批处理（副 LLM，单次调用）**
- `NpcAgentService.decideAllNpcBehaviorsBatch()`
- 预加载每个角色的**限知上下文**（各自目标 + 各自记忆 + 性格 + 见闻 + 背包）
- **一次 LLM 调用**输出 JSON Map：
  ```json
  {
    "charA": {"behavior":"ATTACK","speech":"...","innerThought":"...","isLying":false,"personalGoal":"..."},
    "charB": {"behavior":"INTERVENE","speech":"...","innerThought":"...","isLying":true,"personalGoal":"..."}
  }
  ```
- 角色之间看不到彼此的私有信息（限知博弈本质）
- 失败 → Fallback：所有角色忽略
- **落库**：NPC 决策日志，每回合每角色一条（论文级可追溯）

**步骤 6 · Pass2 叙事生成（LLM + 记忆注入）**
- `Pass2Service.generateNarrativeWithMemory()`
- **记忆上下文注入**（`PlayerMemoryService.buildContextForPrompt()`）：
  - 短记忆（最近若干轮交互摘要）
  - 场景记忆（场景级摘要）
  - 全局记忆（关键剧情转折点）
- Prompt 拼接：记忆上下文 + 规则结算结果 + 事实清单（属性变化 + 关系变化）
- 输出：叙事行 `narrativeLines[]`、谎徽标 `lieFlags`、隐藏总结 `hiddenSummary`
- 落库剧情总结表

**步骤 7 · 目标推进（LLM）**
- `PlayerObjectiveService.advanceObjectives()`
- 以玩家动作 + 结算结果 + 事实清单为输入，评估每个目标进度/步骤/状态
- 落库 `player_objective`，返回是否推进标记

**步骤 8 · 记忆记录**
- `PlayerMemoryService.recordRoundMemory()` 写入本回合短记忆（引用交互日志 id）
- 按周期聚合为场景级记忆

## 九、角色为什么会思考 / 为什么限知 / 为什么会交互

### 9.1 为什么会"思考"

系统给每个角色注入了**独立的**：

1. **秘密目标**（`npc_goal` 表）
2. **独立记忆**（`npc_memory` + 世界书中该角色亲历的事件）
3. **性格与私有见闻**

Prompt 明确要求：以自身视角生活与参与事件，不是回答工具；自行决定动机、心理、言语、行动；玩家沉默时依自身事务选择调查/接应/攻击/离开/对话；新目标只能从真实处境产生。

并强制输出：
- `behavior`：行为类型（ACT / RESPOND / ATTACK / SUPPORT / OPPOSE / IGNORE / LEAVE / INQUIRE / GIVE）
- `speech`：公开台词
- `inner_thought`：真实内心（仅自己知道）
- `personal_goal` / `goal_basis` / `goal_success` / `goal_tradeoff`：个人目标及其依据/完成条件/代价底线

**"思考" = LLM 基于该角色的限知上下文，产出内心活动 + 个人目标。**

### 9.2 为什么"限知"

- **数据库层**：每个角色有独立的目标、记忆、私有见闻录。
- **Prompt 层**：只注入该角色自己的上下文块；其他角色的秘密不注入。
- **规则层**：明令禁止读取他人心理、禁止知道他人秘密（"不知道时不能补造亲历或真相"）。
- 每个角色只读取自己参与过的世界书事件。

### 9.3 为什么会"交互"

**硬性交互（规则引擎驱动）：**
- P1 符咒抵消：守方有符 → 自动抵消
- P2 背刺反转：第三方曾被背刺且信任低 → 劫掠救援
- P3 第三方干预：三角模型得分足够 → 主动出手
- P4 正面对抗：双方属性差决胜负
- P5 贿赂/交谈：按 `actualBen` 判断是否接受

**软性交互（群戏行为驱动）：**
- `ATTACK` / `SUPPORT` / `OPPOSE` / `RESPOND` / `INQUIRE` / `GIVE` 均指向具体对象
- 角色有独立目标，会主动推进；交涉有连续性（记得之前谁说了什么）

## 十、如何判定角色带着什么（物品与符咒判定）

### 10.1 存储

背包存于 `god_profile.inventory`，为 JSON 数组，例如 `["止水符", "骨刃", "解毒丹"]`。

### 10.2 匹配引擎 `InventoryMatcher`

| 方法 | 方式 | 用途 |
|------|------|------|
| `hasExact` | 完全相等 | 精确判定是否持有某物 |
| `containsSubstring` | 子串包含 | 玩家说"用符" → 匹配含"符"物品 |
| `hasCategoryTalisman` | 符类分类（符/咒/印/阵/幡/令） | 判定是否持有符类 |
| `resolveActualItem` | 精确优先 + 子串兜底 | 返回背包中真实存在的物品名 |

### 10.3 符咒抵消判定（P1）示例

1. 玩家输入"我用骨刃刺向对方" → Pass1 解析 `intent=ATTACK, itemId=骨刃`
2. 校验玩家确实持有"骨刃"（`hasExact`）
3. 检查守方背包是否符类（`hasCategoryTalisman`）→ 命中则抵消攻击并消耗该符
4. 未命中则进入 P2 → P3 → P4 → P5 依次判定

### 10.4 物品转移

- `GIVE`：给予 → 双方背包同步增减
- `STEAL`：抢夺成功 → 物品从目标移入玩家
- 贿赂成立：可能触发物品转移

## 十一、说谎判定与全知视角

### 11.1 说谎如何判定

**判定条件：** 某角色的 `speech` 与 `inner_thought` **自相矛盾** → 判定为说谎。

- 群戏层：LLM 输出 `is_lying`
- Pass2 层：LLM 生成叙事时对每条台词再判 `isLying`
- 展示层：前端全知视角读取该标记并高亮

### 11.2 视角差异

| 信息 | 入梦人（限知视角） | 全知视角 |
|------|-------------------|---------|
| 公开台词 | ✅ | ✅ |
| 内心活动 | ❌ | ✅ |
| 说谎标记 | ❌ | ✅（高亮） |
| 六维属性实时值 | ❌ | ✅ |
| 规则中间分 | ❌ | ✅ |
| 分层记忆 | ❌ | ✅ |
| 群戏决策日志 | ❌ | ✅ |
| 物品持有 | 仅自己 | 全部 |

**机制：** 所有信息都已落库，视角开关只决定前端展示范围，不重新生成内容。

## 十二、阶段六：打听机制（属性驱动加权采样）

**服务：** `InquiryService.processInquiry()`

流程：

1. 读取打听者的 **闻** + **慧**。
2. **门槛过滤**：
   - 能触及的最高重要度由 `闻 + 慧` 决定（感知越高，越能发现高重要度事件）
   - `闻 + 慧` 达到阈值才可见"秘密"事件（`is_secret = true`）
3. **加权采样**：权重随重要度平方增长（高重要度事件更可能被抽中），避免纯随机漏掉核心线索。
4. **准确度**：由 **慧** 决定（`baseAccuracy = 60 + min(30, 慧/3)`）。
5. 从世界书查该地点符合条件的事件返回。
6. 写入角色记忆（记录打听事件）。

**论文表述：** 属性驱动的加权采样打听机制。
**六维咬合：** 闻决定"能发现多少"，慧决定"能理解多深 + 信息准不准"。

## 十四、阶段八：死亡、结束与时空回溯

### 14.1 死亡 — `POST /api/game/death`

- 结算中生命归零或触发剧情杀 → 会话状态置为死亡，LLM 生成死亡叙事
- 返回：死亡叙事 + 结局类型 + 目标完成统计

### 14.2 时空回溯（事件溯源）— `GET /save-points` / `POST /load-to-round`

**服务：** `SaveLoadService.loadToRound()`

核心逻辑（**不复制全量世界，仅按回合号裁剪事件**）：

1. 找到目标回合对应的日志边界。
2. **删除**交互日志中 `回合号 > N` 的记录。
3. **删除**世界书中 `会话 + 回合号 > N` 的记录。
4. **删除**角色决策日志中 `日志 id > 边界` 的记录。
5. **删除**对应短记忆。
6. **恢复**玩家位置到第 N 回合的场景。
7. **恢复**会话状态（死亡 → 进行中）。

**优点：** 零冗余存档（50 回合只需 1 个回合标记），读档 = 精准 DELETE，性能远优于全量快照重建。
**论文表述：** 基于事件溯源（Event Sourcing）的轻量级时空回溯引擎。

### 14.3 重启 — `POST /api/game/restart`

- **重承天命**：继承上局世界书历史
- **重新化生**：全新世界，清空历史

两者均重置六维与背包，并回到角色创建流程。

## 十七、设计哲学与论文级表述

1. **"本"是核心放大器**：所有属性实际值受其修正；同时作为贪腐倾向度量，一物两用。
2. **"闻 + 慧"咬合打听**：感知决定广度，推理决定深度，数值引擎与叙事机制自然耦合。
3. **5 层优先级保证剧情多样性**：从硬克制到软对抗到观察，覆盖全谱。
4. **三角模型让角色有"人味"**：能力 / 意愿 / 利益三因子，使第三方干预基于关系网与利益的理性计算。
5. **纯函数 + 事务分离**：规则引擎纯函数可单测，事务层负责落库，职责清晰、便于论文逐段解析。
6. **集中式多智能体提示**：多角色群戏单次 LLM 调用，保留限知博弈本质，同时把延迟压到单次调用量级。
7. **事件溯源时空回溯**：以回合号裁剪事件，实现零冗余的轻量级读档。

## 附：防坑规则落地要点

1. **玩家输入鲁棒性**：无关输入 / 恶意注入 → `UNKNOWN`；规则引擎对 `UNKNOWN` 不报空指针，触发通用氛围旁白。
2. **LLM 输出解析鲁棒性**：JSON 模式 + 正则兜底 + Fallback，重试上限后走本地预设，绝不白屏。
3. **会话隔离**：所有数据带会话标识，查询按会话过滤，禁止全表扫描。
4. **场景移动**：禁止预设出口按钮，玩家以自由文本驱动，拓扑图动态生成。
