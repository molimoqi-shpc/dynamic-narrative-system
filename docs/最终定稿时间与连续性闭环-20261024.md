# 最终定稿时间与连续性闭环（2026-10-24）

## 机制修复

此前允许主API在发表前修正文，却冻结初稿耗时：改好的正文仍可能绑定旧时钟。最终流程是：主API创作候选稿 → 跨日篇章专注定稿正文与时间 → 从唯一最终稿只读归档 → 保存同源人物经历、世界书与下一章交接。专注定稿只提供本篇候选正文、上一篇实际末尾和重大决策边界，不提供旧耗时或玩家预计天数；重要事件与玩家决策保留。随后归档不能再改正文或另估时间。

定稿给出相对于同一起点0的少量累计时间位置，程序只取最后一个位置换算，不将同一天的多场戏相加。真实正文可以超出玩家预计的天数写到有结果，耗时随同一份最终稿保存。普通生活的写作指引改为按有因果变化的场景推进，减少无必要的逐日编号和机械天数总结。

这次实测证明单靠继续加归档提示仍会算错，因此最终方案对跨日篇章增加一次专注定稿调用；单一短场景不增加。早期单独计时的固定0起点探针将旧稿“第5、6、6、7、8、9日”正确读为9天，未重复加同一日；该次约¥0.004225。但单读时间不能修正文含混，所以最终把正文定稿整体移到结果归档之前。定稿原文与原始候选均留存；归档中断只续接相应阶段，不重抽成功的角色与主创。没有逐句模拟、日期关键词许可或剧情可达性判定。先前报告“维持所有每轮调用数不变”不再代表最终实现。

起点绑定上一段已发表原文末尾和logId，不按两篇各自的“第几日”相减。原稿及原时间私有留存；已发表补归档不能重写既有正文和时钟。普通归档顶层估计不能覆盖作者耗时。

完整稿优先，正常稿可用unchanged节约输出；最小合法定稿和嵌套归档均兼容。完整稿缺失或错误单位不再偷偷沿用旧数；只续接保存的归档，成功角色与主创不重抽。旧局部锚点缺失、重复或重叠时不部分发表一稿、却保存另一稿的记忆。

新增了严格有限的格式兼容：仅在追加一个最外层右括号即可完整解析时补该括号，不补字符串、字段值或任意内层残片；保留原回复及修复标记。内部对象中的已知归档字段移到对应根字段，避免人物经历与最终位置被漏读。主API若仅在characterChanges给出某角色本人经历原因和变化，可按同一roleId保存该条本人资料，已有完整roleExperiences优先；不从全局故事推测其他人的所知。

定稿提示要求先以少量原句说明阶段衔接，再定同一稿；能解释通但容易误读的概述也须消歧，不用替原句另换起点辩解。正常跳日、回忆和全篇总结不重复计时，不补成每日流水账。编辑阅读说明仅为私有原回复，不进入角色世界知识；时间basis不添加未发生的新经历。

## 真实发现与处理

第一轮只读重放：模型返回后已收费，但旧provider丢掉不可解析的归档原文。该缺陷现已修复，STORY_ARCHIVE与STORY_AUTHOR一样将原文交给操作层持久保存，不自动付费重抽。失败费¥0.047450已计入，旧原文已丢失，不能冒称可以找回。

第二、三轮只读重放：接口通过，但人工阅读确认旧稿“第二日清早→如此过了两三日→第三日下午”含混仍未修清，故两次均不列作文学验收通过。第三轮提供的原文锚点有替含混句子辩解的情况，随后明确修订要求，未继续反复付费重放旧稿。

step20正常推进时遇到缺失外括号与嵌套归档，完整收费原文被保存；人工阅读又发现跨夜仍吞回第七日，未通过。step21通过恢复完成了正文修订，但计时仍把含第五日至雨歇次日的正文记成八天，且人物亲历字段遗漏，人工拒绝把它列为通过。第一次精简计时按阶段累加又把同一天的两段重复算成十天一小时，也判失败。最终改为固定起点累计位置，针对同一实际正文正确返回九天；本次只读探针未改旧已发表存档。

专注定稿曾尝试启用推理，一次请求在返回用量前超时；已停用该模式，不自动重试。该请求仍以UNCONFIRMED保存，不能声称收费为零，已按请求输入上界和最高8192输出token预留¥0.07。

随后部署最终实现，正常回溯独立测试档到修屋后的第8轮，沿用同一方向生成step25，再根据实际母亲疲劳的结果续玩step26。两章实际完成并连续推进13个游戏日，保存到第10轮，仍PLAYING；没有手改主角状态、代写故事或把只读模型回放冒充正常游玩。第一章发现便利来源字段漏传，已修代码与回归，第二章实际确认；第一章原payload未篡改。所有失败分支、原回复、回溯与费用均保留。
