# 主 API 故事写作提示词说明

更新日期：2026-10-20。

## 接入方式

`backend/src/main/java/com/bs/narrative/service/StoryCraftPrompt.java` 保存共享写作提示，`StoryFirstContract.PROMPT` 和兼容入口 `SceneStoryService.STORY_CONTRACT` 均包含它。

游玩过程中，正常生成、补齐人物意愿、查询世界书、内部接续及候选重写均经 `SceneStoryService.write` 携带完整系统提示。角色 API 仍提供自己的档案与意愿，主 API 统一创作最终正文、对白、经过与结果。

写作指导随原有请求发送，不增加规划、评论、润色等额外模型调用；每次主创请求会多携带这段固定提示，因此输入 token 会有所增加。无需每轮重新联网，也不向外部写作网站发送角色表或存档。

## 联网阅读与取舍

| 来源 | 吸收的方法 | 项目中的取舍 |
|---|---|---|
| [Sudowrite：Story Bible Template](https://sudowrite.com/blog/story-bible-template-how-to-build-one-and-how-sudowrite-does-it-for-you/) | 人物、世界资料、前文、题材与场景目的应相互关联；资料随经历更新 | 继续使用已有角色附加表、世界书、累计摘要与最新正文，写作从这些资料出发；不预定玩家未来选择 |
| [Prompt InFlow：Scene Generator](https://promptinflow.com/prompts/creative-storytelling-scene-generator) | 明确本段目标、阻碍、转折与结束状态，场景应带来变化 | 吸收目标、因果和阶段结果；不照搬固定三次升级、每场必反转、人物不能同意等硬性要求 |
| [FictionAI：50 Templates That Work](https://www.fictionai.pro/blog/ai-writing-prompts-for-fiction-50-templates-that-work) | 第 22、24—29、39—45 项涉及场景结果、因果升级、张弛、公平转折、潜台词、过渡与具体描写 | 从已有经历提取动机与表达差异；不套用凭空增加童年、创伤、秘密等人物生成栏目，也不复制其多轮生成流程 |

这些资料提供可借鉴的方法，网站自身的效果、效率和模型优劣宣传没有作为本项目验证结论。

## 本次写作要求

1. 接在已发布正文的实际终点，围绕本段核心事件写起因、经过与阶段结果。得到答案、解决问题、关系变化、合理受阻及温暖释然都可以构成进展。
2. 冲突从人物已有目标、利益、价值观和关系中产生。配角有自己的诉求，合作与拒绝都有依据。
3. 对白体现各人的语言习惯、态度和透露范围；通过玩家可感知的言行表现潜台词，不直接公开私有心理。
4. 转折联系已有线索和选择，关键困局依靠行动与铺垫解决。线索到可解答时兑现，阶段事件和主线允许收束、高潮与结局，不无限续添谜团。
5. 普通过程概述带过，关键场景适当展开；紧张之后允许日常、休息和关系沉淀。感官细节服务人物与事件。
6. 普通问句不自动成为玩家停点；真正改变重大关系、义务或风险的选择仍停在玩家表态之前。
7. 参考《红楼梦》的日常人物关系、《西游记》的阶段事件与结果、《基督山伯爵》的因果与伏笔回收，仅借鉴通用技法，不挪用原作人物、设定、桥段或原文。

以上用于指导主 API 创作，没有增加地点、时间、关键词或故事质量评分判定，也没有让程序按固定模板决定剧情。返回结构、记忆回写及角色知识隔离沿用现有流程；构思、大纲、评分与创作说明不作为玩家正文输出。
