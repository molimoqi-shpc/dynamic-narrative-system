# 角色知情隔离与天眼过去排版

## 根因与取舍

原先角色个人记录已按存档、角色隔离，但 `StoryAuthorContext.bindRoleRequest` 将完整 `playerInput` 复制到每个角色的 `narrativeRequest`，角色提示再要求不要将其当作自己已知。玩家输入混有公开行动和私下计划时，模型已接触到不应获知的原文。新增人物和已保存的未完成请求也使用这条链路。

比较了三种处理：关键词拆分不可靠，容易误解否定和转述；额外模型过滤会增加调用与费用，并引入另一份不确定的分类；采用已有输入模式和角色归属，从服务端限定交付内容，不新增模型调用或剧情门禁。

## 实现边界

- 普通行动完整原文继续提供给主创。角色只按本人记录、已知消息、当前处境、目标和稳定人设提供意愿与条件，主创负责把这些意愿与玩家方向结合。
- 明确选择“亲自交流”时，仅首段的指定对象收到已保存的原话，标记为尚待主创处理实际送达的对白提案。其他角色不预先收到该原话；后续段落使用本人已经发表的经历，不重复发送旧提案。
- `RoleRequestContext` 在模型请求边界保留角色自有字段白名单，移除自由行动原文及意外附带的全局上下文。新增人物不再携带玩家原始方向。
- 旧操作续接时，对仍需调用模型的角色请求重新投影；已经成功的角色结果保留。旧不安全请求下未完成的候选不重新作为助手消息发送，原始记录仍留存，不修改已发表故事。
- 输入重新整理保持稳定序列化顺序，避免恢复时缓存身份漂移。缺失或错误归属的恢复资料不会被改名后交给另一角色。

本修改控制实际发送的数据范围，不声称模型不会推测或生成错误。已保存经历的内容仍依赖主创正确记录；不批量改写历史记忆，也不靠剧情关键词中止续写。

## 天眼过去的呈现

原界面用同一递归字段组件展开所有个人记录，经历、心理、物品、位置和时钟混排，且每层字段都增加竖向缩进。

现在“独立记忆”内区分经历与心迹、状态与物品。默认展示个人经历和想法，保留所有状态资料供切换查看，筛选不请求模型、不改变数据。正文和旧档案中的编码文字整理为连续段落；时间和来源集中展示；短标签横向换行；标量资料采用标签和值的横向行，嵌套分组保留完整阅读宽度。意愿标记为尚未发生，详细模板与状态可以展开。

读取过20条真实已保存记录，其中19条可展示，包含个人经过、意愿、位置、物品和时钟。格式投影不修改原数据。浏览器工具初始化仍报 `failed to write kernel assets: 系统找不到指定的路径`，未完成实屏截图验收，不能把组件测试说成视觉实测。
