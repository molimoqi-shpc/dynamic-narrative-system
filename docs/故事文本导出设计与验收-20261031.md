# 故事文本导出

## 范围与入口

在主页“继续游戏”的每张存档卡、正式游戏“往事”的页头提供“导出故事”。正式游戏左下角另有“导出”小按钮，位于“此间、留声”下面、“主创”上面，直接导出当前存档。

三处复用同一组件和接口。左栏变体使用与现有工具相同的原生按钮结构，继承字体、细线、悬停和移动端工具栏样式；下载期间显示“导出中”并禁用重复点击。主页导出不要求先切换或激活那个存档。

文件为带 UTF-8 BOM 的 TXT，使用 Windows 换行，保留中文、引号与正文分段。文件名含世界名、主角名和存档分支，清理控制字符及 Windows 非法文件名字符。此功能用于阅读与留存故事，不是可导入的游戏备份。

导出顺序为公开世界介绍、完成开局后保存的初始故事、按回合排序的全部已发表故事，以及已经生成并保存的终章和评价（如有）。仅有初始故事、尚未进行第二轮的存档也可导出。

## 方案选择

不能直接拼接浏览器当前加载的往事：往事分页每次只有40条，长档会缺章。也不应再让主 API 整理小说，否则增加费用，还可能改写已经发生的故事。

采用后端只读导出：在一个可重复读事务里读取同一份存档快照，每次最多读取100条记录并顺序写入响应。没有把整部长篇小说一次性收集到 JVM 内存，也没有增加导出表、额外剧情版本或新模型请求。

导出进行时，下一轮保存或回溯不需要等待导出完成；后续分页仍读取导出开始时的同一快照，避免旧开头配上新分支结尾。身份和归属在写入文件前检查，空档在发送附件响应前拒绝。

## 文本与隐私边界

- 正文只取已发表的 `interaction_log.processed_dialog`，复用现有往事的公开段落与人物显示名解析。
- 开局只取已完成的 `character_creation.birth_story`。公开世界设定只读取标题和介绍。
- 不导出玩家答题、原始操作输入、角色私密心理、模型候选、原始 JSON、提示词、密钥、费用或历史废弃分支。
- 未完成或取消的操作如果已经保存公开正文，保留并标记“已留存片段”；空白占位不算一章。
- 终章仅在终局状态下读取主角自己的公开 `death_summary`、`final_evaluation`，不导出该记录的其他字段。
- 开头重复的旁白序列化标签仅在导出文本中去除，不修改数据库或原有往事。

## 下载失败和并发

文件最后有“—— 故事文本导出完毕 ——”。浏览器收到完整响应并确认此标记后才启动本地下载；JSON 错误、HTML 响应或截断文件会显示可重试提示。

按钮独立显示忙碌并阻止重复点击。组件销毁或目标存档变化时取消请求；下载前再次核对账号、登录凭证和请求归属。旧账号的迟到响应不会保存文件，也不会弹出其错误详情。同一存档的回溯允许已经开始的快照导出完成。

导出不调用模型，不推进时间、回合或修订，不改变活动存档，不重生成已有故事，不自动重试收费流程。
