## 公共修复

归档改用一份本次地点目录，再让人物引用该目录：

```json
{
  "endingPlaces": {
    "returnRoad": {"locationName": "旧驿道回程路", "opening": "三人正在回程，尚未抵达驿舍。"},
    "saltStore": {"locationName": "城东盐栈", "opening": "管事留在仓内。"}
  },
  "endingCast": [
    {"roleId": "主角已有编号", "placeKey": "returnRoad"},
    {"roleId": "同伴已有编号", "placeKey": "returnRoad"},
    {"roleId": "管事已有编号", "placeKey": "saltStore"}
  ]
}
```

主API仍决定实际发生的事及每个人的最终所在。程序仅按目录绑定：名称与已建立地点唯一、完全一致时复用编号，其余按主API明确给出的地点建立记录。新格式里的旧sceneId不覆盖placeKey；同一地点只定义一次，避免同行者各写一段不同的动作描述而分裂成多个地点。

旧已付费回复、旧sceneOutcomes与旧endingCast继续兼容。可选地点资料缺失不会由程序猜测谁同行、到达或离开，也不会自动展开路线、检查旅行条件或追加模型调用。既有错误存档尚未经主API重新归档，不能说已经自动纠正。
