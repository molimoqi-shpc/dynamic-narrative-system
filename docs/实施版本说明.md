## 一、可玩流程与入口

1. 注册、登录：`/api/auth/register`、`/api/auth/login`。BCrypt 保存密码，JWT 及服务端 token 哈希负责身份与吊销，会话归属在控制器之前检查。
2. 开始与恢复创建：`/api/game/start`、`/api/game/creation`。三问原答案、已接受天赋及已完成出生故事均可恢复。相同答案重试复用天赋；相同天赋重试复用已出生角色，不重复调用模型或生成角色。
3. 天赋与出生：`/api/game/answer`、`/api/game/talent/select`。天赋增益由服务器实际施加；缺少必要出生故事或场景时保持可重试，不提交空世界。初始角色、物品及其来源随会话保存。
   物品表不完整时最多自动局部修正一次，冻结已经生成的故事、场景与人物名单；修正表仍须满足角色覆盖、物品归属与场景原文依据检查。不能用修正补造装备。
4. 行动：`POST /api/game/operations` 接受自由文本或明确交流，返回操作标识；`GET /api/game/operations/{id}` 查询进展。玩家可交流、观察、交手、移动、探索、给予/借还物品或等待。旧 `/action`、`/explore` 等入口兼容转入同一操作链。
5. 恢复：`/{id}/recover` 续接技术中断；`/{id}/cancel` 仅取消未发生部分。已接受选择、已发生话语、物品变化与世界时间不会因恢复而重演。输入被解析成心想时，前端要求澄清真实含义。
   已授权探索却收到虚构目的地 MOVE 时，整批状态变更回滚，保留原行动并最多局部修正一次；新地点必须提供完整 EXPLORE 事实包。探索上下文明示抵达时所需的效果结构，并解释“地图未登记连接”属于技术状态，不能编成道路封闭的剧情证据。没有探索授权时不能借修正创建路线。界面对行动结果核验中断与人物决策中断分别提示。
6. 目标：`/api/game/objectives`。新局目标具备服务器可检验的条件，进度根据真实状态推进，不采信模型自报百分比。
7. 终局：通关或死亡后停止接受新行动，显示结局、目标统计、回溯、继承重开、全新重开和返回主菜单。结局弹窗挂载到页面顶层，操作按钮使用两列布局，窄屏下也能完整显示。
8. 存档：`/api/game/sessions`、`/resume`、`/save-points`、`/load-to-round`。刷新和继续游戏从服务器恢复，回溯同时恢复生命、属性、背包、关系、目标、场景、记忆和未完成操作。
   新局初始化即建立 branchEpoch=0 / revision=0 的运行记录；旧局缺失运行记录时场景接口也提供明确的零版本，避免第一步行动之前陷入前端同步等待。

## 二、六维、交手与生命

`StatsCalculator` 与 `StatFormulaBook` 共用六维 V2 公式：成长曲线 C、神职系数 M、辅助属性调和协同 S。知、慧、斗、闻、本、归保持原含义，基础本限制 0～100。界面可打开每项公式及中间值。

普通交手使用服务器实际斗值：阈值 T=max(10, round(0.10×双方实际斗之和))，差值超过阈值判优势，否则平局。指纹核对角色、身体、数值和生命原状态，状态变更后的旧候选不得直接提交。

新增独立生命值，初始 100，存在 `role_knowledge` 的 `VITAL_STATE` 中。交手败方扣 25，平局双方扣 5，胜方不扣。只有真实提交的 CONTEST 效果应用损耗；生命归零才产生本轮死亡结局。六维下降、忠诚为零、模型一句“已死”均不能代替生命规则。生命记录包含在检查点，回溯会精确恢复。

原 `ConflictResolver` 的五层裁决仍用于旧规则服务和引擎演示。当前开放执行链不会仅凭物品名字中有“符”就赋予魔法，也不会因第三方数值高就强迫其干预。特殊能力需要明确机制；未知效果返回待处理，不在正文里伪造成功。

## 三、目标与通关

模型为新局提出 2～3 个目标及结构化条件。开局仅接受持有既有物品、抵达既有场景、实际观察既有场景、探访地点数量、亲耳听见指定既有人物的话，以及 AND / OR / NOT 组合。禁止用虚构地点、资源或知识引用建立目标，也禁止把“理解秘密、了解争执、探明退路”等认知写成设施物理状态。设施状态条件仍供已有明确世界机制使用，不用于自动生成开局目标。

没有足够可验证条件、目标无效或全部开局即达成时，回退为两个明确目标：实际观察初始场景、亲自探访两个不同地点。模型失败不会让目标永远卡在零。目标面板展示服务器返回的完成方法与实际进度，组合条件和探访数量可显示部分进度。重新初始化时先落库删除旧目标，再插入新目标，避免同名唯一键冲突。

新局会明确登记“完成本组初始目标”的终局规则，全部完成后会话进入 VICTORY。旧存档的个人目标不会被默认为新终局；已有显式终局规则仍保留。死亡状态优先，通关检查不能覆盖死亡。

## 四、独立 NPC 与事实边界

NPC 根据各自已收到的信息、记忆、目标、身体、物品与独立思考时钟决定言语和动作。同刻角色先冻结上下文，再并行请求；每名角色的私有上下文独立。

选择、执行、实际发言与收件分别记录在操作 payload 和角色记录中。全知面板可以查看后台选择；未说出口的候选台词不会被显示为实际公开对白。入梦模式不返回 NPC 后台心理。

角色交涉仍有自由立场。打听须指定实际信息来源，询问由角色依据自身见闻回答；闻、慧的信息筛选与准确度规则保留在 `InquiryService` / `WorldBookService`。高属性不提供跨角色秘密访问权。

角色反应现在明确区分收到话语、自主注意与自身动作结果。没有话语、也没有后续意向的 `AFTER_ACTION` 不再额外请求一次反应；同一角色已有待决策任务时合并结果触发。新消息会接续已经发生的交谈和仍未说完的话，不按台词文字强制去重，角色仍可主动重复拒绝、催问或保持沉默。等待别人答话由消息与独立思考时钟触发，不作为每个例行动作完成后的再次决策意向。

场景内走近、退回、挪步等移动意愿以 `localMovement` 标记，仍保留完整原文及约束。成功或进行中的移动结果必须提交执行者位置变化，不能仅在正文中描述；遗漏时最多局部修正一次。真实受阻且未移动时保留原位置，不为补齐字段伪造移动成功。位置与最近所见随状态检查点保存。

场景接口只读取已激活存档的玩家位置。请求尚未恢复的另一份存档时返回明确的数据冲突，缺失场景也返回业务错误，不把错误对象当成成功场景交给前端。

天眼追溯先按时间排序少量操作编号，再按主键读取 JSON 内容；不对整份大 JSON 排序，避免多角色长记录触发 MySQL 排序内存不足。读取过程中保持一致的分支视图，不修改数据库全局内存配置。

2026-10-17 补充身体与场景边界：每份执行结果最多一次 MOVE / EXPLORE，抵达后只可附 OBSERVE。出发前的实际交物和身体变化仍按发生顺序提交，到达后的新交涉或设施操作须在新现场另行结算，不能继续沿用出发地点资源。服务器在写入前检查效果顺序，防止已经离开却隔空交物、操作旧设施或用旧位置覆盖抵达位置。失去意识的 BODY 必须位于效果末尾，不能睡下后继续执行其余效果。

角色身体上下文明确提供服务器 health / alive，区分生命归零和暂时昏迷。普通 BODY 唤醒不能复活；死亡角色只能保存无效果的真实受阻经过，不能继续行动。活着的昏迷角色仍可正常苏醒，苏醒不补生命。每个效果提交前重新核对执行者生命，避免同份结果中交手耗尽生命后仍继续执行后续效果。这些事实/顺序错误沿用每个工作最多一次局部修正的预算，再次不合格则停为 PARTIAL，不无限重试模型。

### 2026-10-18 盟约自然回应与条款一致性

明确自然表达如“我接受你提出的结盟提议”“你的结盟提议，我同意”“我同意这份结盟提议”可记录同意；“结盟就不必了”“我不愿/不想与你结盟”记录拒绝，不继续挂成待回应。仍要求已经完整交付给明确对象，不将上一轮真实样例中只答应互不交手的回应升级成结盟。

完整话语中的相反声明或“只是说说、不算数”等限定不再仅凭第一句同意生效；接受时明确重申的期限必须与原提议一致。先说同意、又说“期限改为十秒”，不能偷偷按原三分钟成立，也不擅自替双方采用十秒新约。复杂协商仍保留为待明确同意。

随后真实澄清中复现“是，我应你”没有关联原问题而仍为待回应。新增受限的上下文同意：只读取服务器冻结给当前 NPC 的单一实际收件刺激，并核验双方都已完整收到的原结盟确认问题；须明确指向按原提议结盟，时间与原约一致，简短同意的后文不得反悔、改条件或另说不结盟。不将一般“是/同意”、回答其他问题或旧对话关联成结盟，也不回写已完成的旧真实操作。新增 8 项关联检查，最终目标集合为 43 项规则与 5 项默认操作整链。

### 2026-10-18 双方结盟与持续盟约

默认对话新增标准双边盟约，记录在各当事人的 TREATY 中。只有调度器已经证明完整交付给明确对象的话语才可建立提议或同意；“我提议与你结盟”“我同意与你结盟”等明确表达可以形成 PROPOSED → ACTIVE，单方宣布、沉默、提问、引语、条件句和冲突表态不会替代对方同意。第三人不会凭空获得当事人的结构化盟约；其实际听见的话仍按原话语机制保存。盟约不强制增加信任、忠诚、援助或跟随，不替角色决定心理。

首批支持固定标准条款：双方互不主动发起交手，各自保留行动判断，任何一方可明确解除。可以持续至解除/破盟，也可明确提出秒、分钟或小时的期限，最多一天，期限从受邀者完整说出同意时开始。支持拒绝、撤回、解除、到期及双方确实感知的交手破盟；过期不自动续约，不能将未感知的隐藏意图直接广播成背叛。复杂资源交换、附加条件、多人联盟、条款协商或远程解除尚未接入，不将标准双边盟约称为任意复杂契约。

NPC 每次后续思考读取自己的持续盟约，明确区分待回应、已生效与已结束。真实收到可识别的 NPC 结盟提议，即使模型漏填 player_decision，故事模式也会停在 ALLIANCE，等待人类回应。不会自动替玩家答应。可见盟约进入“见闻与约定”，接受、拒绝、撤回、解除按钮只填入亲自交流草稿；对方不在最近所见人物中时不通过按钮远程送达。盟约快照不能作为普通消息转送给第三人，玩家可自行用话语转述。

提议、同意和结束保留实际话语、来源事件和故事时间。沿用原短事务、存档和回溯：回溯到同意前恢复待回应，回溯到提议前不保留未来盟约。综合测试额外修复交手来源使用 kind、盟约校验只认 recordType 导致实际交手不破盟的问题，并补全交手事件的实际目标标识。
