# 天眼角色资料可读化修复

用户反馈：昨天在“誓匠”相关存档开启天眼查看其他角色时，介绍直接显示 JSON 和内部数据。已定位到世界“誓书未干”的存档 `sess_05b3900caeab4a9ba64bdf81409`，主角为爱法诺，其他角色为奈雅、米拉·萨恩、贝洛。

## 根因和选型

原天眼复用了给模型准备的完整角色上下文。共用组件 `DossierFields` 仅根据 JavaScript 类型决定显示方式：对象展开，字符串直接输出。旧档中的 `identity.establishedSelf` 实际是“数组里的 JSON 字符串”，因此直接出现在界面。部分 `ownKnowledge` 则是“检索记录头＋JSON”的拼接文本，普通 JSON 解码仍不足以处理。

此外，组件未区分玩家资料与模板版本、模型说明、内部编号、索引游标及立绘匹配代码；意愿栏直接插值对象时也会被 Vue 展示成序列化文本。记忆栏还直接展示了供主 API 使用的分层提示词。

比较后选择只读展示适配：

- 不删除括号或截掉字符串：这样会损失人物来历、关系和心理信息。
- 不重写所有旧档或变更模型上下文协议：问题属于显示职责，改写保存数据会牵连故事与费用。
- 在共用展示层解码、命名和整理记录，保留原始数据供故事系统使用；天眼与世诰共用修补结果。

## 修改结果

- `dossierPresentation.js`：识别完整 JSON、数组中的编码字符串、多层编码及 JSON 围栏；把已知检索记录格式拆成可读条目；隐藏内部说明和模板元数据。
- `dossierLabels.js`：补齐人物来历、来源、关系、状态、性别、外观年龄段等中文标签。时间和来源代码按既有值翻译，不重算故事时间。
- `DossierFields.vue`：递归显示经过整理的资料。已知人物、地点和物品编号替换为当前响应中提供的名字；缺失姓名时不编造身份。保留 false、零值、普通引号和自然正文；异常旧记录显示可读提示，保留 Vue 文本转义，限制异常深层展开。
- `PerspectivePanel.vue`：意愿也使用资料展示组件；记忆排除内部索引记录，并使用中文类别。取消对主 API 分层提示词的直接输出；原有个人记忆列表和分页仍可使用。
- `WorldBookPanel.vue`：历史条目中的 JSON 字符串同样交给共用组件，避免在世诰里再次作为普通正文输出。

不把立绘匹配的 `archetype`、`culturalStyle` 代码作为人物真实介绍显示。没有修改立绘匹配逻辑、故事生成、后台协议、角色原始数据、视角状态、导航或输入框，也没有新增预览路由。
