# Persona 界面方向研究与后续改版约定

记录日期：2026-10-24。作者：睦子米。

## 本轮范围与用户最新意图

用户否定了“悬影灯卷”v6，希望重点参考 https://asia.sega.com/p3r/cn/ 的动画，结合 Persona 5 的图形语言与人物展示；人物不再仅限古风，用户提供了写实幻想人物图。用户说“或许会剔除神明强设定，更改为随机世界观”，这是候选设计方向，并非已经确定的机制改造命令。

本轮只阅读、交互研究和保存笔记。没有改前后端代码，没有换正式素材，没有生成新概念图，没有调用收费故事 API，也没有安排明天自动执行。等用户下一次指令再开始改造。

先前 v5/v6 仍可作为历史产物保留，但不应再当作用户认可的最新视觉终点。下次不能继续只给古风纸景换光、加细边。

## 核心理解

用户要的是具有完整风格和鲜明节奏的游戏界面。人物、背景、标题、菜单形状和转场应当共同构图；不能继续依赖“左边立绘加背景、右边纸页、下方统一按钮”的固定配方，也不能把动效缩水成所有模块淡入几百毫秒。

P3R 与 P5 的共同优点在于界面本身具有作品性格，但二者表现不同：本次P3R首屏的水面、倒置轮廓、留白、波形过渡，与P5笔记中的转折箭头、剪报字和锐角分镜并不相同。不能把二者混称成一套“红黑斜切模板”。

人物美术也不必完全复制 Persona 的二次元风格。可以吸收其抠出轮廓、放大裁切、前后遮挡和动作节奏，同时使用用户偏好的写实幻想人物。需要用统一的色调、边缘、受光和构图把人物与图形界面结合，不能直接将写实图贴在卡通背景上。

## 素材实现判断

在P3R人物详情中，直接读取当前页面图片元素可见，主角日常形象与战斗形象分别使用WebP图片（文件名含 img_character1 与 img_character1_battle）。所以这个“3D渲染感切换”至少在该详情展示处，可以由预渲染二维素材完成；不能据此推断全站没有实时3D。

本项目可用透明人物图、独立轮廓影、SVG遮罩、可控背景纹理实现主体效果。真正的头发/衣摆柔性运动，需要独立分层素材或骨骼；单张图片只能产生整体轻移与有限视差，不能声称与完整Live2D或3D人物等效。明天先做可交互原型，避免再次用漂亮静态图掩盖动态不足。

## 随机世界观：候选设计影响

用户只是提出可能性，当前不删除神明系统、世界设定、六维或现有存档。若后续确定：

- 界面外壳与题材分开：基本操作位置、可读性和交互语言一致；主题改变背景、配色、图形纹理和世界标题。不为每种世界重新生成一套不可控UI。
- 人物类型不限古风：现代、写实幻想、历史等素材按世界风格和角色身份筛选，不把年龄/性别类型当作角色唯一身份。
- 同一存档中的重要人物维持固定形象。新角色有稳定的素材映射，不能每回合随机换脸，不能因“随机世界观”把所有NPC配成幻想女性。
- 首轮可以采用少量风格一致、覆盖性别年龄的立绘库，缺少素材的龙套使用经过设计的剪影/文字卡，避免每名NPC都必须收费生图。
- 若去掉神明强设定，文案、世界创建、提示词、终局和既有存档兼容需要一起评估，不能只换首页名称就宣称完成。
- 角色API提供行动意愿与即时/过往附加表，主API生成故事；上下文连贯、长期可玩、限知/全知的原有要求继续有效。

## 下一次动工时的顺序

1. 重读本笔记与用户下一条具体指令。先确认该条指令是否确定世界观变更；未确定时只改视觉外壳与预览。
2. 先用现有本地预览建立一套真正可点击的动效样机：主阅读态、人物册开合、两个角色切换、世界书入口、重大选择态。必须包含真实转场，而不是只输出静态概念图。是否先出新图仍按用户当时要求。
3. 选一个原创图形母题，试验人物轮廓、标题、背景与菜单共同运动的方案；不要直接套P5黑白红或P3蓝色水纹。
4. 再定最终美术与补制角色素材，解决写实人物和图形界面的融合；将随机世界观作为独立待定范围处理。
5. 针对视觉原型做响应式、键盘、减少动态、快速开关、切换途中取消与长文可读性验收。使用封闭模拟数据，不花故事API预算。
