## 已修复并针对性复测

1. 开局重要持物不再要求说明逐字包含物品名或复制正文原句。保留归属编号和可保存格式等技术要求，避免有效开局被字符串匹配挡住。
2. 新人物漏写最终地点时，保存身份、经历和处境，不再默认传送至主角身边。旧 EXPLORE 协议明确列在新场景里的居民保留原有兼容行为。
3. 无所在地记录的角色可按主创请求提供本人的过往与意愿；上下文不套用主角现场，不泄露现场观察，也不因准备上下文自动移动人物。已见过的异地人物不每轮都自动调用。
4. 每个主创片段的归档输入补齐本段停点、玩家目标、已有公开卡状态；明确重大提议尚待选择、普通结账自然处理，数字与收付保留来源。公开卡单独提到归档输入前部，仍由主 API 从玩家实际见闻补 playerView，不直接复制作者秘密。
5. 修复“只回 story 就绕过归档却标为完成”的保存缺口。现在正文照常保留，主 API 的同次归档负责补缺失耗时与末态；归档缺字段时只恢复归档，不重抽角色、不重写正文。为最新且尚未被后续章节推进的旧 story-only 记录增加显式补归档恢复，防止重复发表同章。
6. 主创写作上下文加强：不重复支付已付船费/押金；离场者不能凭空一直在门边；不能先替玩家答应再询问；证词矛盾不整理成已证实事实。这些属于创作引导，实际效果按下方原文评估。

本轮相关回归累计覆盖 **121 个不同测试**：GenesisInventoryTest 3、CreationFlowIT 11、StoryArchiveServiceTest 12、StoryArchiveIT 22、SceneStoryIT 65、StoryPlotIT 7、StoryCastPlacementIT 1。中间暴露的兼容与新增恢复失败已修复，并复跑对应失败项。测试使用模型替身，不计入上述付费调用，不将它们算作 121 次真实游玩。日志在工作区 work/continuous-20261023-*.log。

## 实际阅读评价

- 第 1～2 轮有完整调查动作与证人，但三十二两、八两、十五两、九两的含义前后不严，德昌六两一会说收一会说付。第 3 轮虽尝试解释，仍把收到的六两和付出的三两合称已支未销，不能视为核账正确性通过。
- 第 3 轮有已经离场的何掌柜被写成一直站在门边的错误；归档后来修正了位置，但没有改写原文，因此正文连续性仍留有缺陷。
- 第 4 轮确实三日抵青溪、租房、求职并在新条件前停下；但重复描写了第 3 轮已支付的船脚。后续已补写作引导，没有为隐藏错误重抽这轮。
- 第 5 轮恢复后自然跨半月。东家回应记实、不作保的边界；老陈有带教过程，秤差产生处理与认可，普通工作没有再逐条弹窗。篇幅偏重账务细节，但能形成阶段变化。
- 第 6 轮实际结清二百文工钱，续住只收新半月七十文、不重复收押金，并与刘木匠重逢、教记工单，世界没有因完成旧目标而结束。仍有同一段先说“凭据先开、银后补”，又说“凭据后补、银已先付”的矛盾；系统保存完整不代表文学与逻辑已完全可靠。
- 时间字段现在能够保存，但第六轮应承接“已工作半月”推进到满月，补归档却给了新增 30 天，存在把累计跨度当本段增量的问题。没有因此阻止故事推进，但精确时间一致性尚未通过，未用程序改判剧情或暗改原文。
- 世界书：仍显示过期状态：余九两短账、查余九两的章程待定。提示词与公开卡输入已补强，但本次不能宣称这些卡已全部同步。
- 阶段目标：仍为 ACTIVE 的目标：为来年开春南下青溪城寻长久营生做准备；应结合最终正文判断是否为归档遗漏，不能把状态值当成故事进展。
